# ARUT-HARDT Character & Ragdoll Lab

A starter scene for testing the built-in C++ ARUT component source after building an ARUT editor from the `engine-first-cpp-ux` branch.

## What this scene contains
- One `ArutCharacter3D` node; its default humanoid dummy, capsule collision and third-person camera are generated by C++ at runtime.
- Native character movement with walk/sprint, jump, friction and air control.
- A connected, procedural 11-body ragdoll with cone-twist joints, activated from the character.
- An `ArutRenderProfile3D` node using the Mobile preset, a lit floor, a rigidbody crate and a minimal mobile touch-hint overlay.

## Controls
- **Desktop:** WASD or arrow keys move, Space/Enter jumps, Shift sprints; press **R** to drop into ragdoll.
- **Phone:** drag the left side to move; drag the right side to turn/look; bottom-right tap jumps; mid-right hold sprints; top-right tap starts ragdoll.
- Ragdoll activation is one-way in this first pass. The character does not yet recover/get back up or blend from animation to physics.

## Import/run
1. Build/install the ARUT editor from the `engine-first-cpp-ux` branch's Android workflow.
2. Extract this folder into phone storage.
3. In ARUT, import the project by selecting this folder's `project.godot`.
4. Open `main.tscn` and press Run Project.

The node types are native engine classes: do not replace them with GDScript versions. This prototype's rigid bodies and joints currently call the active Godot `PhysicsServer3D`; it is **not yet an independent ARUT physics solver/backend**. The PhysX 5 Godot integration investigated so far is work-in-progress and has no Android ARM64 build path ready to use. Choosing or implementing a different backend is still an outstanding engine task documented in `docs/PHYSICS_ARCHITECTURE.md`. This disclosure is intentional so a working ragdoll prototype is not misrepresented as a new solver.
